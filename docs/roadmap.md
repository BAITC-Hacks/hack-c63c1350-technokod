# Дорожная карта разработки. Кейс «Agentic AI для прогнозирования выработки ВЭС» (Самрук-Казына)

Старт 13:00, финиш 18:00 (Астана). Контрольные коммиты в :55 каждого часа.

## Цель
Агент, который для каждого дня тестового периода (31.01 → 01.02 … 27.02 → 28.02.2026) сам берёт архивный прогноз погоды, доступный на момент прогноза, готовит признаки, запускает модель, выдаёт почасовой прогноз выработки двух турбин на 24–48 часов, проверяет результат и пересчитывает при обновлении входных данных.

## Архитектура (слои)
1. `app/data.py` — загрузка CSV организаторов (10-минутки), агрегация в часы, чистка.
2. `app/weather.py` — инструмент погоды: Open-Meteo Previous Runs API (прогноз, выданный за 1 и 2 дня до каждого часа) и Historical Forecast API (архив прогнозов для обучения). Кэш в `data/cache/`.
3. `app/features.py` — признаки: скорость ветра 100 м и 10 м из прогноза, порывы, направление, температура, давление, час, день года, лаги фактической выработки на момент прогноза.
4. `app/model.py` — модель: градиентный бустинг (sklearn HistGradientBoosting) по турбинам плюс базовая кривая мощности как fallback. Метрики MAE, RMSE, nMAE.
5. `app/agent.py` — оркестратор Agentic AI: цикл «получить погоду → подготовить → прогноз → анализ → пересчёт». LLM (OpenAI, резерв NVIDIA NIM) через function calling выбирает инструменты, объясняет результат, решает о пересчёте при обновлении прогноза.
6. `app/backtest.py` — воспроизведение прошлого: последовательные запуски агента на каждый день 31.01–28.02, результат в `outputs/forecasts/*.csv` и сводный `outputs/forecast_feb2026.csv`.
7. `app/cli.py` — команды: `fetch-weather`, `train`, `forecast --date`, `backtest`, `report`.
8. README, `make demo` (скрипт `scripts/demo.sh`), режим проверки без ключей.

## Риски и решения
- Архив прогнозов за 2023 отсутствует в Previous Runs API. Обучение на Historical Forecast API (архив прогнозных моделей) за весь период, валидация на Previous Runs за 2025–2026.
- Часовые пояса: данные ВЭС в местном времени, Казахстан перешёл на UTC+5 в марте 2024. Погода запрашивается с `timezone=Asia/Almaty`, стыковка по локальному времени.
- Пропуски в данных (T1: 41 дней в июне–июле 2024). Строки без факта исключаются из обучения, не интерполируются.
- Лимиты API: кэш всех запросов на диск, прогон бэктеста без сети из кэша.
- Бюджет LLM: модель дешёвая на рутину, сильная только на анализ результата. Все ответы кэшируются для DEMO_MODE.
