# ADR 0001. Источник погоды: архив прогнозов, а не факт

Статус: принято, реализовано (`app/weather.py`).

## Контекст

Кейс требует, чтобы для каждого дня использовался прогноз погоды, доступный на момент прогнозирования.
Нарушение этого требования — прямое несоответствие задаче, даже если ошибка модели окажется низкой.
В выданных данных есть только показания датчика гондолы самой турбины, внешнего прогноза нет.

## Варианты

1. **Факт погоды из реанализа** (ERA5, Open-Meteo Archive). Даёт лучшие метрики и неверен по сути:
   на момент выпуска таких данных не существует.
2. **Показания анемометра гондолы как вход модели.** Тоже факт, причём измеренный самой турбиной, и на
   момент прогноза он недоступен.
3. **Archive Previous Runs API** (`previous-runs-api.open-meteo.com`): для каждого часа хранит значения
   из прогонов, выпущенных за 1 и за 2 дня до него.
4. **Historical Forecast API**: непрерывный архив прогнозных моделей, но лид 0–24 часа и без явной
   привязки к дате выпуска.

## Решение

Единственный источник погоды для прогноза — Previous Runs API через `forecast_available_at(site,
issue_date, 48)`: часы 1–24 горизонта берутся из слоя `*_previous_day1`, часы 25–48 — из
`*_previous_day2`. Оба слоя содержат значения прогонов, выпущенных не позже даты выпуска.

Обучение ведётся на том же источнике (`previous_runs_training`): на каждый исторический час берутся оба
слоя, то есть модель учится на тех же ошибках прогноза погоды, которые увидит в тесте. Historical
Forecast API остался только как инструмент разведки данных и в итоговую модель не входит.

## Последствия

- Утечка факта исключена конструктивно: другой функции получения погоды в контуре прогноза нет.
- Обучающий период сокращается: архив Previous Runs начинается с 16.02.2024, то есть теряется 2023 год
  и начало 2024. Объём обучения после стыковки с фактом — 31 078 часо-примеров для T1 и 33 710 для T2.
- Метрики честные и сопоставимые с эксплуатацией: январь 2026 прогнозируется «как в прошлом», по одному
  выпуску на каждый день.
- Зависимость от одного внешнего провайдера. Смягчение — дисковый кэш в репозитории (ADR 0005).
