# Как работать с проектом

Документ для тех, кто продолжает разработку WindAgent: как поднять окружение, чем проверять изменения и по каким правилам оформлять вклад.

## Окружение

Эталонное окружение, на котором выполнены все замеры: Python 3.14, pandas 3.0.6, scikit-learn 1.9.1, openai 3.19.0. Минимально достаточная версия Python — 3.11.

```bash
git clone https://github.com/BAITC-Hacks/hack-c63c1350-technokod.git
cd hack-c63c1350-technokod
python -m venv .venv
# Windows:        .venv\Scripts\activate
# Linux / macOS:  source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # Windows: copy .env.example .env
python scripts/check_env.py
```

`python scripts/check_env.py` печатает версию интерпретатора, наличие данных, обученных моделей, размер кэша прогнозов и состояние ключа LLM. Отсутствие ключа не считается ошибкой: решение полностью работает без него.

Модели в репозиторий не коммитятся: pickle привязан к версии scikit-learn, чужой `.joblib` на другой версии не загружается. Первый запуск требует обучения, оно занимает около 15 секунд (кэш прогнозов в репозитории, сеть не нужна):

```bash
python -m app.cli train
```

## Проверка изменений

```bash
python -m pytest -q tests          # 22 теста, без сети и ключей, около 4 секунд
bash scripts/demo.sh               # полный контрольный сценарий (Windows: powershell scripts/demo.ps1)
```

Контрольный сценарий проходит 7 шагов: проверка окружения, обучение (пропускается, если модели уже есть), выпуск прогноза, бэктест февраля, сводка, автотесты, живая LLM-оркестрация (пропускается без ключа). На обученных моделях занимает около 20 секунд, на свежем клоне — около 40 секунд вместе с обучением.

Если изменение затрагивает модель, признаки или агента, артефакты нужно перегенерировать и приложить к тому же коммиту:

```bash
python -m app.cli train
python -m app.cli backtest --no-llm
python scripts/make_charts.py
```

## Структура репозитория

| Путь | Назначение |
|---|---|
| `app/` | Код решения: загрузка данных, погода, признаки, модель, агент, бэктест, CLI, HTTP-сервис |
| `scripts/` | Обучение, проверка окружения, построение графиков, контрольные сценарии для жюри |
| `tests/` | Автотесты основного сценария, работают без сети и ключей |
| `data/raw/` | Данные организаторов: 10-минутные записи двух турбин |
| `data/cache/weather/` | Кэш архивных прогнозов Open-Meteo, закоммичен ради запуска без сети |
| `models/` | Обученные модели, не коммитятся, создаются командой `train` |
| `outputs/` | Результаты: выпуски прогноза, журналы агента, итоговый ряд февраля |
| `docs/` | Проектная документация: архитектура, агент, модель, валидация, испытания, регламенты |
| `assets/` | Иллюстрации для README, строятся `scripts/make_charts.py` |
| `.github/` | CI и шаблоны issue и pull request |

## Коммиты

Conventional Commits: префикс на английском, описание на русском.

```
feat: добавить интервал P10-P90 в выпуск агента
fix: исправить выбор квантилей по лиду прогноза
docs: обновить README — раздел проверки решения
refactor: свести два класса агента в один
test: добавить тест детерминированного выпуска
chore: обновить зависимости
ci: настроить сборку через GitHub Actions
```

Правила: глагол в инфинитиве, без точки в конце, заголовок не длиннее 72 символов. Тело коммита отделяется пустой строкой и объясняет, зачем сделано изменение, а не что именно изменилось — это видно из диффа.

## Pull request

Шаблон подставляется автоматически (`.github/PULL_REQUEST_TEMPLATE.md`). Перед отправкой: тесты проходят, документация обновлена, `.env.example` актуален, артефакты перегенерированы, если менялась модель.

## Секреты

Ключи провайдеров LLM хранятся только в `.env`, он в `.gitignore` и в репозиторий не попадает. В `.env.example` лежат имена переменных с пустыми значениями. В журналах агента и в выводе CLI ключи не печатаются — только признак «задан / не задан». Если ключ всё же попал в историю, его нужно немедленно отозвать у провайдера: удаления коммита недостаточно.

> **Про CI.** Workflow `.github/workflows/ci.yml` настроен и корректен, но в репозитории
> хакатона он не выполняется: организация-владелец заблокирована по биллингу, GitHub
> отвечает «The job was not started because your account is locked due to a billing issue».
> Поэтому проверка выполняется локально: `python -m app.cli train` и `python -m pytest -q tests`,
> либо контрольный сценарий `bash scripts/demo.sh` целиком.
