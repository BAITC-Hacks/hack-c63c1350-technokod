# ADR 0004. Детерминированный планировщик как обязательный откат LLM

Статус: принято, реализовано (`app/agent.py`, `run_day`).

## Контекст

Кейс требует агентного контура, то есть оркестрации инструментов моделью. Но жюри должно воспроизвести
результат без ключей и без сети, а на хакатоне внешний API — это лимиты, таймауты и чужие сбои. Кроме
того, модель может закончить диалог, не вызвав сохранение, и тогда выпуска просто не будет.

## Варианты

1. Только LLM-оркестрация. Красиво по духу кейса, но невоспроизводимо и хрупко.
2. Только детерминированный план. Воспроизводимо, но не соответствует требованию агентности.
3. Два режима поверх одного набора инструментов, с автоматическим переключением.

## Решение

Инструменты — единственная реализация логики; оркестратор сменный. При доступном провайдере порядок
вызовов выбирает модель через function calling. Любая из ситуаций — нет ключа, `DEMO_MODE`, ошибка сети
или лимита, модель не вызвала `save_forecast` — приводит к откату: в трассу добавляется запись
`llm_fallback` с типом и текстом ошибки, расчётное состояние сбрасывается (`_reset_state_for_fallback`),
выпуск переигрывается фиксированной цепочкой
`get_weather → prepare_and_predict → analyze → [recalculate] → save_forecast`.

Заключение в режиме без LLM собирается из тех же чисел анализа (`_plain_narrative`), поэтому структура
результата и журнала одинакова в обоих режимах.

## Последствия

- Жюри воспроизводит весь бэктест без ключей (`--no-llm` по умолчанию) и получает те же числа.
- Агентность проверяема: `llm_used` в журнале и трасса инструментов показывают, кто выбирал порядок.
- При откате детерминированный план проходит цикл заново с первого инструмента, поэтому частичный
  результат модели не смешивается с планом. Ошибка отдельного инструмента откатом не считается: она
  возвращается модели как `{"error": …}`, и та исправляет порядок вызовов сама.
- Цена: логика решений продублирована в промпте и в `_deterministic`; при изменении правил надо править
  оба места. Пороги при этом одни (`CUT_IN`, `RATED`, `STORM`, `UPDATE_THRESHOLD`) и живут в коде,
  а не в промпте.
