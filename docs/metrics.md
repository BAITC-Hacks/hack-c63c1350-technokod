# Качество модели

Числа взяты из `docs/metrics.json`, файл перезаписывается при каждом обучении (`python -m app.cli train`).

## Протокол измерения

Проверка воспроизводит рабочий режим: для каждого дня января 2026 берётся прогноз погоды,
который был доступен **на этот день**, и по нему считается выработка на 48 часов вперёд.
Факт погоды не используется ни в обучении, ни в проверке; факт выработки участвует только как
эталон при сравнении. Январь 2026 в обучение не входит.

- Горизонт 24 ч — часы 1–24 (прогноз погоды, выпущенный за сутки, lead 1), 720 часов января.
- Горизонт 48 ч — часы 25–48 (прогноз, выпущенный за двое суток, lead 2), 720 часов.
- Мощность нормирована на номинал (0..1), поэтому MAE в долях номинала, а nMAE = MAE × 100 %.

## Веса смеси

Подбираются на той же честной валидации, отдельно по турбине:

| Турбина | кривая мощности | двухстадийная | бустинг |
|---|---|---|---|
| 1 | 0.5 | 0.5 | 0.0 |
| 2 | 0.6 | 0.4 | 0.0 |

Прямой бустинг «признаки прогноза → мощность» переобучается на исторические совпадения и на
честной проверке проигрывает обеим физическим моделям, поэтому его вес равен нулю: в рабочем
прогнозе он остаётся только как отдельная колонка для сравнения.

## Интервал неопределённости

К точечному прогнозу считается интервал P10–P90 по квантилям остатков, раздельно для горизонтов
24 и 48 часов и для четырёх уровней прогнозной мощности (штиль, разгон, рабочая зона, номинал):
ошибка в середине кривой мощности в разы больше, чем на штиле и на полке.
Фактическое покрытие интервала на январе 2026 — **79.6 %** при целевых 80 %.

## Как повторить

```bash
python -m app.cli train    # перечитает данные, переобучит, перезапишет docs/metrics.json
python -m app.cli report   # печатает эти же числа из docs/metrics.json
```
