# Программа и методика испытаний

Документ описывает, как проверить решение WindAgent независимо от разработчиков. Все проверки выполняются из корня репозитория на чистой установке.

Обозначения команд: `PY` — интерпретатор виртуального окружения, то есть `.venv\Scripts\python.exe` в Windows и `.venv/bin/python` в Linux/macOS.

## 1. Объект испытаний

| Параметр | Значение |
|---|---|
| Объект | WindAgent: агент прогнозирования почасовой выработки двух турбин ВЭС на 24–48 часов |
| Версия | 0.1.0 (см. `CHANGELOG.md`) |
| Состав | `app/` (data, weather, features, model, agent, backtest, cli, llm, config), `scripts/`, `tests/`, `data/raw/`, `data/cache/weather/`, `docs/` |
| Входные данные | CSV организаторов (10-минутные записи 11.03.2023–31.01.2026), архивные прогнозы Open-Meteo Previous Runs |
| Выходные данные | `outputs/forecasts/<дата>.csv`, `outputs/agent_logs/<дата>.json`, `outputs/forecast_all_issues.csv`, `outputs/forecast_feb2026.csv`, `outputs/backtest_summary.csv` |
| Среда испытаний | Python 3.10+ (эталонный прогон: Python 3.14.2, pandas 3.0.6, scikit-learn 1.9.1, openai 3.19.0), Windows 11 и Linux, опционально Docker |

## 2. Критерии приёмки

Привязка к критериям оценки кейса.

| Критерий оценки | Вес | Что должно быть доказано испытаниями | Проверки |
|---|---|---|---|
| Соответствие задаче | 25 | Горизонт 24–48 ч с шагом час по двум турбинам; для каждой даты выпуска используется только прогноз погоды, доступный на эту дату; реализован полный агентный цикл с пересчётом | П-04, П-05, П-06, раздел 4 |
| Техническое исполнение | 25 | Модель обучена и валидирована по честному протоколу, метрики воспроизводятся, код проходит автотесты | П-03, П-11 |
| README и воспроизводимость | 25 | Чистая установка по инструкции, контрольный сценарий целиком без ключей и без сети, совпадение с заявленными числами | П-01, П-02, П-08, П-09, П-12 |
| Ценность | 15 | Выходные артефакты пригодны для заявки на рынок и планирования резервов: почасовой ряд февраля без пропусков, интервал P10–P90 | П-06, П-07 |
| Оригинальность | 10 | Агентная оркестрация через function calling с откатом, детектор обновления входных данных, двухэтапная модель | П-05, П-10 |

Решение считается принятым, если все проверки П-01…П-13 имеют результат «пройдено», а раздел 4 («проверка честности прогноза») подтверждён. Проверки П-10 и П-13 требуют ключа провайдера; без ключа они помечаются «неприменимо», и это не влияет на приёмку — решение рассчитано на работу без ключей.

| П-12 | Запуск в Docker | `docker compose build`<br>`docker compose run --rm app bash scripts/demo.sh` | Контрольный сценарий целиком проходит в контейнере | Код возврата 0, в контейнере созданы те же артефакты, что в П-04 и П-06 |

Контрольный сценарий целиком — семь шагов, эквивалент П-02 → П-03 → П-04 → П-06 → П-07 → П-11, и седьмым шагом П-10, если задан ключ (без ключа шаг пропускается с сообщением): `bash scripts/demo.sh` в Linux/macOS, `powershell -File scripts/demo.ps1` в Windows. Скрипты сами выбирают интерпретатор (`PYTHON` → `.venv` → `python`), останавливаются на первой ошибке и пропускают обучение, если модели уже есть. Замер: 20 секунд на обученных моделях, 38 секунд на чистом клоне с GitHub вместе с обучением.

## 4. Проверка честности прогноза

Ключевое требование кейса: для каждого дня используется прогноз погоды, доступный на момент прогнозирования, а не фактическая погода. Ниже — места в коде и наблюдения, которыми это проверяется.

| Что проверяем | Где смотреть | Как убедиться |
|---|---|---|
| Запрашиваются только архивные выпуски прогноза | `app/weather.py`, функция `previous_runs`: в параметр `hourly` уходят только поля вида `<переменная>_previous_day1` и `_previous_day2` | В запросе нет ни одной переменной без суффикса `_previous_dayN`; ответы лежат в `data/cache/weather/`, параметры запроса восстанавливаются из ключа кэша |
| Окно прогноза сдвинуто в будущее относительно даты выпуска | `app/weather.py`, функция `forecast_available_at`: окно начинается с `issue_date + 1 день`, часы 1–24 берутся из слоя `previous_day1`, часы 25–48 — из `previous_day2` | Оба слоя выпущены не позднее `issue_date`; тест `tests/test_pipeline.py::test_forecast_available_at_uses_only_past_runs` проверяет границы окна и разметку `lead_day` |
| В признаках нет фактических измерений | `app/features.py`, список `FEATURES` | В списке только величины из прогноза погоды и календаря; фактические колонки `wind_ms` (анемометр гондолы) и `power_norm` в признаки не входят. Команда контроля: `grep -n "wind_ms\|power_norm" app/features.py` — совпадения только в целевой переменной и в стыковке факта при обучении |
| Обучение идёт на том же типе входа, что и тест | `scripts/train.py`: обучающая погода берётся из `previous_runs_training`, валидация — помесячным повтором `forecast_available_at` | Распределение признаков в обучении и в тесте одинаковое, факт погоды не участвует |
| Прогноз погоды не является «переодетым фактом» | `docs/metrics.md`, раздел «Основной источник ошибки» | Корреляция прогнозной скорости ветра на 100 м с измеренной на гондоле 0.67: ряды существенно различаются, подмены факта нет. Проверяется расчётом из `docs/validation.md` |
| Тестовый период не пересекается с обучением | `scripts/train.py`: обучение до 31.12.2025, валидация январь 2026, финальные модели дообучены до 31.01.2026 | Тест 01.02–28.02.2026 лежит строго за границей обучающих данных |

## 5. Негативные проверки

| № | Ситуация | Как воспроизвести | Ожидаемое поведение |
|---|---|---|---|
| Н-01 | Модели не обучены | Удалить `models/`, выполнить `PY -m app.cli forecast --date 2026-02-06 --no-llm` | Понятное сообщение с подсказкой выполнить `python -m app.cli train`, без трассировки стека |
| Н-02 | Нет сети и пустой кэш | Отключить сеть, временно переименовать `data/cache/weather/`, выполнить `PY -m app.cli forecast --date 2026-02-06 --no-llm` | Осмысленное сообщение о недоступности источника прогнозов, ненулевой код возврата, повреждения артефактов нет |
| Н-03 | Неверный ключ LLM | Указать в `.env` заведомо неверный `OPENAI_API_KEY`, выполнить `PY -m app.cli forecast --date 2026-02-06 --llm` | Откат на детерминированный план, запись `llm_fallback` в трассе, прогноз всё равно получен |
| Н-04 | Дата вне покрытия архива | `PY -m app.cli forecast --date 2023-05-01 --no-llm` | Сообщение об отсутствии архивных прогнозов на эту дату (Previous Runs покрывает период с 16.02.2024), без частичного или пустого файла прогноза |
| Н-05 | Некорректный формат даты | `PY -m app.cli forecast --date "не дата" --no-llm` | Ошибка разбора даты, ненулевой код возврата; поведение закреплено тестом `test_bad_date_rejected` |
