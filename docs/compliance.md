| OpenAI API | Оркестрация агента через function calling и текстовое заключение | Ключ участника, кредиты хакатона; тарификация по токенам | `OPENAI_API_KEY` в `.env` |

Ключи хранятся только в переменных окружения и в `.env`, который исключён из репозитория (`.gitignore`, строка `.env`). В коде, логах, журналах агента и выходных файлах ключи не появляются. Все ответы внешних API кэшируются на диск (`data/cache/`), поэтому контрольный сценарий воспроизводится без сети и без ключей.

## 5. Использование ИИ-инструментов разработки

Разработка велась с применением ИИ-агентов для генерации и анализа кода (п. 5.4.12 Положения). Раскрыто в README, раздел «Стороннее и подготовленное до старта». Все решения по архитектуре, выбору источника данных, протоколу валидации и составу модели приняты командой; результаты работы ИИ-инструментов проверены автотестами и численными экспериментами, зафиксированными в `docs/validation.md` и `docs/metrics.md`.

Отдельно: LLM в самом продукте используется как оркестратор агента — выбирает порядок вызова инструментов и пишет заключение. Числовой прогноз она не формирует: значения считает обученная модель (`app/model.py`), которая вызывается одинаково в обоих режимах. Поэтому контрольный сценарий и бэктест по умолчанию идут без LLM (`--no-llm`), и результат воспроизводится без ключей.
