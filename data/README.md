# Данные

## `raw/` — данные организаторов кейса

`turbine_1.csv` и `turbine_2.csv` — записи двух турбин ВЭС с шагом 10 минут за период
11.03.2023 – 31.01.2026 (T1: 142 360 строк, T2: 149 499 строк). Колонки исходных файлов:

| Колонка | Смысл | Единицы |
|---|---|---|
| `ID` | порядковый номер записи | — |
| `Статистическое время` | метка времени, местное время площадки | `ГГГГ-ММ-ДД ЧЧ:ММ:СС` |
| `Средняя скорость ветра(m/s)` | средняя скорость ветра за 10 минут по датчику гондолы | м/с |
| `Нормализованная активная мощность` | выработка, нормированная на установленную мощность турбины | 0..1 |
| `Средняя температура окружающей среды(°C)` | средняя температура воздуха за 10 минут | °C |

Пропусков в значениях нет, есть разрывы по времени: у T1 31 разрыв суммарно на 1 658 часов
(крупнейший — 41 день летом 2024), у T2 68 разрывов на 450 часов. Модуль `app/data.py`
приводит записи к часовому ряду; часы, где меньше трёх десятиминуток, помечаются пропуском
и в обучение не попадают. Разбор данных — в `docs/analysis.md` и `docs/data-quality.md`.

Файлы лежат в репозитории, потому что без них решение невозможно воспроизвести. Наружу,
за пределы оценки кейса, данные не публикуются.

## `cache/weather/` — архивные прогнозы Open-Meteo

68 JSON-ответов Previous Runs API и Historical Forecast API по координатам ВЭС, закоммичены
намеренно: благодаря им обучение, бэктест и контрольный сценарий выполняются без сети.
Имя файла — хеш параметров запроса, повторный запрос с теми же параметрами читается с диска
(`app/weather.py`). Чтобы прогреть кэш на новый период: `python -m app.cli fetch-weather --start ... --end ...`.

## `cache/demo_responses.json` — кэш ответов модели

Сохранённые текстовые ответы LLM для режима проверки без ключей (`DEMO_MODE=true`).
Появляется после первого запуска с ключом; на оркестрацию через function calling не
распространяется — без ключа агент проходит тот же цикл детерминированным планировщиком.
