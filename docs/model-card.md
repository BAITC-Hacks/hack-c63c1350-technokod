# Карточка модели выработки ВЭС

Версия: обучение от 23.09.2026. Числа — из честной валидации на январе 2026 (`docs/validation.md`),
машинный вид — в `docs/metrics.json`.

## 1. Назначение

| Пункт | Значение |
|---|---|
| Что предсказывает | нормированную активную мощность турбины, 0..1, с часовым шагом |
| Горизонт | 24–48 часов от даты выпуска (сутки вперёд и двое суток вперёд) |
| Объект | две турбины ВЭС в Шелекском коридоре (43,6451° с. ш. 78,5356° в. д. и 43,6432° с. ш. 78,5388° в. д.), модель обучается по каждой отдельно |
| Пользователь | диспетчер ВЭС и энергосбытовая служба |
| Решение, которое она поддерживает | суточная заявка на рынок, планирование резерва, выбор окна для обслуживания |
| Что подаётся на вход при эксплуатации | только прогноз погоды, доступный на момент выпуска |
| Что модель не получает | фактическую погоду, фактическую выработку, телеметрию турбины в момент прогноза |

## 2. Обучающие данные

| Пункт | Значение |
|---|---|
| Цель | `power_norm` из 10-минутных данных организаторов, усреднённая по часу |
| Период истории | 11.03.2023 – 31.01.2026, 25 392 часа в сетке |
| Период обучения | 16.02.2024 – 31.01.2026 (ограничен началом архива прогнозов) |
| Строк в обучении | 31 078 (турбина 1) и 33 710 (турбина 2) |
| Строк при подборе весов (до 31.12.2025) | 29 590 и 32 222 |
| Источник погоды | Open-Meteo Previous Runs API, архивные прогнозы с лидом 1 и 2 суток |
| Координаты запроса погоды | середина между турбинами, одна точка на обе |

Одна строка — это час с одним значением лида, поэтому каждый час даёт две обучающие строки: каким его
видел прогноз за сутки и за двое суток. Часы без факта (6,5 % у турбины 1, 1,8 % у турбины 2) отбрасываются
и не интерполируются: восстановленная выработка сделала бы оценку качества недостоверной. Подробный разбор
данных — в `docs/data-quality.md`.

## 3. Признаки

Все признаки строятся в `app/features.py` только из погодного кадра и календаря.

| Признак | Физический смысл |
|---|---|
| `wind_speed_100m` | скорость ветра на высоте ступицы, основной предиктор |
| `wind_speed_10m` | приземный ветер, задаёт профиль |
| `wind_gusts_10m` | порывистость, косвенный признак турбулентности |
| `ws100_sq`, `ws100_cube` | квадрат и куб скорости: мощность потока пропорциональна кубу |
| `shear` | разность скоростей 100 и 10 м, вертикальный сдвиг и устойчивость атмосферы |
| `dir_sin`, `dir_cos` | направление ветра без разрыва на 360°, учитывает рельеф коридора |
| `temperature_2m`, `surface_pressure` | температура и давление |
| `air_density` | плотность воздуха по уравнению состояния, множитель в мощности потока |
| `hour_sin`, `hour_cos` | суточный ход |
| `doy_sin`, `doy_cos` | сезонный ход |
| `lead_day` | горизонт прогноза (1 или 2 суток), позволяет модели знать о разной точности входа |

Лаги фактической выработки сознательно не используются: на горизонте более суток они бесполезны
(см. эталон персистентности в `docs/validation.md`, он хуже константы).

## 4. Устройство модели

Три компонента, обучаемые независимо, и их взвешенная смесь.

| Компонент | Что делает | Параметры |
|---|---|---|
| `curve` — кривая мощности | эмпирическая медиана выработки по бинам прогнозной скорости на 100 м, линейная интерполяция между бинами | шаг бина 0,5 м/с |
| `two_stage` — двухступенчатая схема | бустинг предсказывает скорость ветра **на гондоле** по признакам прогноза, затем измеренная кривая «ветер гондолы → мощность» переводит её в выработку | `HistGradientBoostingRegressor(max_iter=500, learning_rate=0.05, max_leaf_nodes=31, min_samples_leaf=50, l2_regularization=1.0, random_state=42)`, шаг бина кривой 0,25 м/с |
| `gbm` — прямая регрессия | бустинг предсказывает выработку напрямую по признакам прогноза | `HistGradientBoostingRegressor(max_iter=600, learning_rate=0.05, max_leaf_nodes=31, min_samples_leaf=40, l2_regularization=1.0, random_state=42)` |

Смысл двухступенчатой схемы: связь «ветер на гондоле → мощность» почти детерминирована (разброс внутри
бина мал, см. таблицу кривой в `docs/data-quality.md`), поэтому задачу выгоднее свести к прогнозу ветра,
а физику турбины взять из измерений, а не выучивать заново.

Веса смеси подбираются перебором по сетке с шагом 0,1 на честной валидации января 2026. Типичный результат:
вклад прямого GBM нулевой, основная масса распределяется между кривой мощности и двухступенчатой схемой
(на последнем обучении 0,5/0,5 у турбины 1 и 0,4/0,6 у турбины 2; между прогонами пара весов может
смещаться на одну позицию сетки — разница в MAE при этом меньше 0,002). Между месяцами оптимум тоже
плавает: на декабре 2025 он уходит в чистую двухступенчатую схему (1,0 / 0,0), и выигрыш от такой
подгонки под месяц не превышает стандартной ошибки измерения (`docs/validation.md`, раздел 8.3).
Устойчиво только одно: вклад прямого GBM нулевой во всех проверенных месяцах.

Почему прямой GBM проигрывает: на 30 тысячах строк он переобучается на комбинации признаков прогноза,
тогда как кривая мощности — это жёсткая физическая связь, которую не нужно выучивать. Внутри обучающего
периода GBM выглядит лучше всех (MAE 0,088), но на честной валидации оказывается худшим компонентом (0,158).

Дополнительно модель отдаёт интервал P10–P90 по квантилям остатков валидации, раздельно для четырёх
уровней прогноза и двух лидов.

## 5. Метрики

Честная валидация, январь 2026, 720 часов на каждый горизонт, нормированная мощность 0..1.
nMAE = MAE × 100 %, так как мощность нормирована на единицу.

| Турбина | Горизонт | MAE | RMSE | nMAE |
|---|---|---|---|---|
| 1 | 24 ч | 0,1431 | 0,2015 | 14,3 % |
| 1 | 48 ч | 0,1633 | 0,2296 | 16,3 % |
| 2 | 24 ч | 0,1455 | 0,2041 | 14,6 % |
| 2 | 48 ч | 0,1666 | 0,2316 | 16,7 % |

Стандартная ошибка этой оценки — около одного процентного пункта (блочный бутстрап по суткам,
720 часов — это 30 коррелированных суточных блоков, а не 720 независимых наблюдений). 95-процентный
интервал: [12,3 %; 16,2 %] для турбины 1 и [12,4 %; 16,6 %] для турбины 2. На соседних месяцах та же
модель даёт 16,2 % (ноябрь 2025) и 19,2–19,7 % (декабрь 2025), поэтому 14,3 % — результат на конкретном
месяце, а не характеристика модели вообще. Разбор устойчивости — `docs/validation.md`, раздел 8.

По компонентам (MAE):

| Компонент | Т1, 24 ч | Т1, 48 ч | Т2, 24 ч | Т2, 48 ч |
|---|---|---|---|---|
| Смесь | **0,1431** | **0,1633** | **0,1455** | **0,1666** |
| Кривая мощности | 0,1471 | 0,1689 | 0,1480 | 0,1697 |
| Двухступенчатая | 0,1493 | 0,1674 | 0,1526 | 0,1731 |
| Прямой GBM | 0,1580 | 0,1796 | 0,1608 | 0,1843 |

Сравнение с эталонами (MAE, горизонт 24 ч):

| Метод | Турбина 1 | Турбина 2 | Насколько модель лучше |
|---|---|---|---|
| Модель | **0,1431** | **0,1455** | — |
| Климатология по часу суток | 0,3003 | 0,3007 | на 52 % |
| Константа (среднее по истории) | 0,3010 | 0,3017 | на 52 % |
| Персистентность (последние полные сутки) | 0,3568 | 0,3463 | на 58–60 % |

На горизонте 48 часов выигрыш сохраняется: 54–55 % против персистентности и 44–45 % против климатологии.

Потолок качества: при точно известном ветре на гондоле та же кривая даёт MAE 0,032 и 0,037. То есть
примерно 78 % текущей ошибки — это ошибка прогноза погоды, а не модели турбины.

Интервал P10–P90 покрывает факт в 79,4 % случаев на горизонте 24 часа и в 79,7 % на 48 часах по обеим
турбинам, при средней ширине 0,42 и 0,51 соответственно (`docs/validation.md`, раздел 7).

## 6. Ограничения

- **Плановые остановы и ограничения диспетчера не моделируются.** В данных нет журнала остановов;
  47 часов у турбины 1 и 26 у турбины 2 с низкой выработкой при сильном ветре остаются необъяснённым шумом.
- **Штормовое отключение не выучено.** За всю историю нет ни одного часа со средней скоростью 22 м/с
  и выше, поэтому поведение турбины в шторм модели неизвестно. Обнуление выработки при прогнозе
  22 м/с и выше сделано правилом агента, а не выводом из данных.
- **Обледенение не учитывается.** Признака наличия льда на лопастях нет; зимние часы с аномально низкой
  выработкой при нормальном ветре модель не отличает от обычных.
- **Разрыв в истории турбины 1.** 18.05–17.07.2024 потеряно около 1 450 часов, в июне 2024 осталось
  4 часа. Обучающая выборка турбины 1 на 1 300 часов короче, чем у турбины 2.
- **Метрика зависит от месяца сильнее, чем от настроек модели.** Разброс между соседними месяцами
  около ±2,5 процентных пункта (14,3 % на январе 2026, 16,2 % на ноябре, 19,2–19,7 % на декабре 2025),
  а стандартная ошибка оценки на одном месяце — около 1 пункта. Любое сравнение вариантов модели
  с разницей меньше пункта на одном месяце недостоверно, и ожидание на феврале нужно строить
  по диапазону 14–20 %, а не по одному числу.
- **Потолок задан прогнозом погоды.** Улучшение модели турбины даст не более пятой части оставшейся ошибки;
  дальнейший рост качества — только за счёт лучшего или ансамблевого прогноза ветра.
- **Одна точка погоды на две турбины.** Расстояние 400 м этого оправдывает (корреляция ветра 0,994),
  но для парка из десятков машин потребуется сетка точек.
- **Нормированная мощность.** Модель не знает установленную мощность турбины, перевод в МВт·ч
  выполняется снаружи умножением на номинал.

## 7. Эксплуатационные риски и контроль

| Риск | Как проявится | Как заметить |
|---|---|---|
| Источник погоды деградировал или сменил модель | систематический сдвиг прогноза ветра, рост ошибки при внешне нормальной работе | агент сравнивает каждый новый выпуск с предыдущим (`analyze`); устойчивое расхождение больше 0,15 по мощности — сигнал разбираться |
| Недоступность API погоды | нет входных данных | инструмент `get_weather` падает с явной ошибкой, кэш `data/cache/weather/` позволяет повторить прошлый выпуск |
| Изменение состояния турбины (ремонт, замена лопастей) | кривая мощности перестаёт соответствовать машине | ежемесячное сравнение факта с прогнозом по диапазонам ветра, переобучение при смещении больше 0,03 MAE |
| Дрейф из-за сезона | ошибка растёт вне зимы | метрики считаются по месяцам, модель переобучается на свежих данных перед каждым сезоном |
| Слепое доверие точечному прогнозу | заявка на рынок без запаса | вместе с прогнозом выдаётся интервал P10–P90 и число часов штиля/номинала |

Модель не принимает решений сама: она выдаёт почасовой ряд и интервал, решение по заявке принимает диспетчер.

## 8. Воспроизведение

```bash
python -m app.cli train
```

Около 15 секунд на двух турбинах при кэше прогнозов из репозитория, сеть не нужна. Результат записывается
в `models/turbine_{1,2}.joblib` и `docs/metrics.json`. Сами модели в репозиторий не кладутся: это
артефакт конкретного окружения, а не исходный код, поэтому проверка всегда начинается с обучения. Полный протокол проверки и допуски — в `docs/validation.md`.
