# ADR 0005. Кэш внешних вызовов хранится в репозитории

Статус: принято, реализовано (`app/weather.py`, `_cached_get`).

## Контекст

Воспроизводимость в критериях кейса весит столько же, сколько сама модель. Решение опирается на внешний
API погоды: без сети или при смене политики провайдера повторить обучение и бэктест невозможно. Кроме
того, обучение и бэктест делают сотни запросов, а у открытого API есть лимиты.

## Варианты

1. Ходить в API при каждом запуске. Просто, но результат зависит от сети и лимитов.
2. Кэшировать во временную папку вне репозитория. Помогает разработчику, не помогает жюри.
3. Кэшировать на диск внутри репозитория и коммитить кэш.

## Решение

Каждый ответ API сохраняется в `data/cache/weather/<hash>.json`, где hash — SHA-256 от url и параметров
запроса. Повторный запрос с теми же параметрами читается с диска и сети не требует. Кэш коммитится
(около 5 МБ, 68 файлов на текущий период), поэтому `train`, `forecast` и `backtest` повторяются офлайн.

Ответы LLM кэшируются отдельно, в `data/cache/demo_responses.json`, и используются режимом `DEMO_MODE`.

## Последствия

- Контрольный сценарий для жюри выполняется без сети и без ключей — это и заявлено в README.
- Результаты детерминированы: одни и те же входные данные дают одни и те же числа в любой день.
- Кэш неизменяем по ключу: если провайдер пересчитает архив, файл не обновится сам. Для обновления нужно
  удалить соответствующие файлы кэша — приемлемо, поскольку архив прошлых прогонов не меняется.
- Репозиторий тяжелеет на объём кэша. При расширении периода стоит перейти на parquet или на внешнее
  хранилище с фиксацией версии.
