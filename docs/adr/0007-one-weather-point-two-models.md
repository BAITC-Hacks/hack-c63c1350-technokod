# ADR 0007. Одна точка погоды на ВЭС, отдельная модель на каждую турбину

Статус: принято, реализовано (`app/weather.py`, `app/model.py`).

## Контекст

Турбины стоят в 400 метрах друг от друга (43.645150, 78.535604 и 43.643198, 78.538828). Любая глобальная
прогностическая модель имеет шаг сетки порядка километров, поэтому прогноз для двух точек в 400 метрах
физически одинаков. При этом сами турбины ведут себя по-разному: у них различаются простои и качество
датчиков, что видно по разным кривым мощности и разным пропускам.

## Варианты

1. Запрашивать погоду отдельно для каждой турбины и учить две модели.
2. Одна точка погоды, одна общая модель на обе турбины.
3. Одна точка погоды (середина между турбинами), но отдельная модель на каждую турбину.

## Решение

Погода запрашивается один раз для точки `FARM` — середины между турбинами. Модель обучается отдельно для
каждой турбины на её собственном факте выработки; веса смеси и квантили остатков тоже свои.

## Последствия

- Вдвое меньше запросов к API и вдвое меньше кэша без потери информации.
- Различия турбин учитываются там, где они реальны: в кривой мощности и в весах смеси. Подобранные веса
  действительно разошлись (T1 — 0.6 / 0.4, T2 — 0.3 / 0.7 для two_stage / curve), значит объединять
  турбины в одну модель было бы потерей.
- Агент сравнивает прогнозы турбин между собой (`turbine_spread_max`): при одной и той же погоде большое
  расхождение — сигнал о проблеме модели или о различии состояния турбин.
- При расширении на парк с разносом в километры одной точки не хватит: потребуется сетка координат и
  привязка турбины к ближайшему узлу (отмечено в `docs/architecture.md`).
